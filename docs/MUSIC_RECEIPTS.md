# Exact music receipt recovery

`lib/music-receipt.ts` recovers the Studio music package from a receipt's actual transaction CBOR. The result includes the original file bytes, release information and every supported credit. A receipt's metadata JSON, declared package hash or saved bundle cannot substitute for the committed transaction metadata.

This is a bounded offline reader for `cip60-v3-studio-exact-files`, the native transaction profile generated by `buildMusicReleaseTransaction`. It is not a general CIP-60 decoder, ledger validator, signature verifier or chain inclusion checker. The music profile remains the CIP-60-aligned Studio extension described in `MUSIC_RELEASE.md`; this reader does not claim broader wallet/player interoperability or verify copyright assertions.

## API

```ts
routeMusicReceipt(C: CSL, parsedInput: unknown):
  'music' | 'ordinary-nft' | 'other';

recoverMusicReceipt(C: CSL, receiptInput: unknown):
  Promise<MusicReceiptRecovery>;
```

Import `CSL`/`loadCSL` from the existing Cardano module. CSL browser-inlined and Node packages are both pinned to 17.0.0. No new runtime dependency is required. The module reuses `canonicalPassportJson` only as the existing bounded plain-data serializer and calls `recoverMusicRelease`/`verifyMusicRelease` from the music package. It does not change the ordinary Artifact Passport profile or its unsupported-music guard.

The route function accepts a JSON-parsed envelope. It reads bounded actual transaction metadata and presence of music declaration fields, without traversing unrelated sidecars. Its answer is only a route selection. `music` must be followed by `recoverMusicReceipt(C, originalJsonText)` before any files or credits are shown as verified. A missing music sidecar cannot hide a transaction's actual `music_profile`, `music_metadata_version` or `music_package_sha256` fields. Declaring music while the transaction has none throws a mismatch.

`recoverMusicReceipt` accepts original JSON text or a plain object. Original text may be pretty or compact and rejects duplicate keys, including escaped aliases. Pass text at an import boundary to apply its whole-file byte/structure bounds. Object input is intended for existing in-memory receipts: it snapshots selected public assertions and deliberately ignores unrelated wallet snapshots. It does not traverse or return those wallet details. Do not stringify an already-parsed imported object before strict verification: that would erase duplicate-key evidence.

Supported inputs are:

- `nft-studio.receipt.v1`, `kind: 'nft'`, with `hash`, `signedHex`, exact `bytes`, `state`, and `createdAt`. Optional `checkedAt` and `blocksAfterInclusion` remain reported observations.
- `nft-studio.review.v1`, `mode: 'nft'`, with `hash`, `unsignedHex`, and `createdAt`. A spread of the existing `MusicReleaseTransaction` works directly.

Types `MusicReceiptPacket`, `MusicReviewPacket`, `MusicReceiptClaims`, `MusicReceiptRecovery`, `MusicReceiptState` and `MusicReceiptRoute` are exported. The runtime input stays `unknown`; TypeScript declarations do not bypass validation.

When present at the top level or inside `prepared`, `hash`, `mode`, `metadataProfile`, `musicPackageHash`, `policyId`, `assetName`, `metadata`, `bundle`, `musicRelease` and `unsignedHex` must match the actual transaction and recovered package. An unsigned sidecar must retain the same raw body, raw auxiliary bytes and sole native policy witness, with no payment witnesses. Unrelated preparation data is omitted from the result.

## What a successful result means

The `status` is `verified-local-content`. The result exposes a frozen `musicRelease`, policy ID, textual and hexadecimal asset name, raw body hash, committed auxiliary-data hash, measured transaction/metadata sizes and payment-witness count.

The reader performs these checks:

1. Parse the exact transaction through a bounded structural CBOR reader, then CSL `FixedTransaction`. Preserve the original body bytes for the transaction hash. Reject trailing bytes, duplicate primitive map keys, nonminimal arguments, excessive recursion/nodes, invalid UTF-8, indefinite strings, unsupported primitives and invalid outer structure before CSL sees the input.
2. Check exact receipt body hash and byte count; require a true script-valid *declaration*. Recompute the auxiliary-data hash and compare it to the body commitment. Require the producer's metadata-only auxiliary encoding, with no auxiliary scripts.
3. Derive identity from a sole quantity-one asset mint. Decode its exact UTF-8 name, recover the music package from actual metadata, and validate file/package hashes and the complete release/credit profile.
4. Check the native producer shape: allowed body/witness fields, nonempty inputs/outputs, one mainnet payment-key recipient across outputs, no output datum/reference script, the minted unit retained once, sole matching signer-plus-expiry native policy, TTL below expiry, fee at or below the Studio 2 ADA cap. Bind the asset name to the recovered package hash and one consumed input using the existing Studio name derivation.
5. Compare supplied public sidecars. Distinguish unsigned reviews with zero payment witnesses from signed receipts with at least one.

The returned `receiptObservation` is explicitly `{ evidence: 'receipt-reported', ... }`. Even `state: 'confirmed'` and a reported block count do not change `checks.chainInclusion: 'not-checked'`.

`checks.paymentSignatures`, `transactionValidity`, `chainInclusion`, `ownership` and `rights` are all `not-checked`. Syntactically present payment witnesses are counted, without claiming that their signatures are valid. Checking a native policy's shape also does not prove the transaction could pass ledger validation. This reader does not query spent inputs, verify conservation against chain state, evaluate timelocks at an actual slot, calculate a current protocol minimum fee, prove authorship or establish legal rights.

No wallet addresses, input references, wallet snapshots, raw transaction hex or raw auxiliary data are returned. The public music package and its exact file bytes are returned intentionally.

## Bounds and errors

| Bound | Limit |
| --- | ---: |
| Original receipt JSON text / selected object projection | 512,000 UTF-8 bytes |
| Transaction CBOR | 16,384 bytes |
| CBOR depth / nodes | 16 / 4,096 |
| JSON depth / nodes | 24 / 20,000 |
| Plain envelope/preparation fields | 128 each |
| Music metadata | 14,000 bytes, inherited from music codec |

The JSON whole-file limit is applied only by strict recovery. Routing lets unrelated large ordinary sidecars proceed to their existing reader. Thus the RecoveryPanel's ordinary 1.5 MB import ceiling can stay intact.

All recovery failures become `MusicReceiptError` with a bounded explanatory message and code. `MISMATCH` means a contradictory checked claim; `UNSUPPORTED_PROFILE` means the packet/native profile is outside this reader; `INVALID_MUSIC_RECEIPT` covers malformed structure or music data. `NOT_MUSIC_TRANSACTION` is the explicit ordinary NFT classification when calling strict recovery directly. Never catch all errors and fall back to generic file recovery.

## Validation evidence

The synthetic verifier runs 11 groups with 82 rejected recovery cases. It exercises both actual shared-builder receipt lanes, browser/Node CSL parity, exact file and credit equality, independent BLAKE2b-256 body/auxiliary hashes through the pinned Noble implementation, sidecar contradictions, credit changes, producer restrictions, ignored wallet internals, duplicate JSON, and malformed CBOR that must never reach CSL. An intentionally invalid synthetic signature demonstrates the deliberately unverified signature boundary.

The sample has 7,195 unsigned transaction bytes, 7,301 bytes after synthetic signing, 6,844 metadata bytes and a 476,801 lovelace fee. The current receipt JSON is 57,605 bytes. No keys are persisted, no provider is called and no transaction is submitted. These measurements describe that fixture, not arbitrary user input.

The existing ordinary Artifact Passport verifier passes all 8 groups. The current actual RecoveryPanel parser also recovers all 9 frozen catalog programs/covers byte-for-byte. The integrated browser checks in `scripts/audit-music.cjs` also pass signed/unsigned recovery, changed and stripped sidecars, duplicate JSON, package import, reported confirmation and large ordinary imports. These are synthetic local checks, with no real wallet, signature-validity or chain-inclusion claim.
